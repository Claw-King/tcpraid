# 概念

## 节点

一个**节点**就是一个正在运行的 `tcpraid run`。它是一个长期运行的进程，有自己的数据目录、自己的身份、一个网页界面、一个本机 HTTP API，需要时还有一个供其他节点连接的监听。每个站点运行一个，可以装在 NAS 本机上，也可以装在为身后机器服务的路由器或网关上。

节点的身份是它第一次启动时生成的一对密钥。公钥的 SHA-256(十六进制)就是节点的**指纹**。只要数据目录还在，指纹就不变。

## 配对和对端

两个节点只需**配对**一次。其中一个生成**配对码**，也就是一长行文字，你把它输入到另一个节点上。之后两个节点各自把对方列为**对端**，它们之间的每一条连接都会做双向认证。

和一个节点配对，就是信任它，因为对端的连接可以去往另一个节点能连到的任何地址，除非你用这个对端的允许列表把范围收窄。允许列表见 `security.md`。

两个节点之间的控制连接连着的时候，`tcpraid peers` 和“对端”页面会把对端显示为**在线**。控制连接是一条很小的连接，由持有路径的节点保持着，每 10 秒发一次保活。

## 路径、角色和子连接

**路径**是节点连到对端的一种方式。它是一个地址，可以经过一个 SOCKS5 代理。配对时会在输入配对码的节点上建一条路径，指向配对所走的地址。一个对端最多可以有 16 条路径。

节点每承载一条应用连接，就在每条路径上打开若干条**子连接**，断掉的会补上。一条路径承担什么，由它的**角色**决定：

| 角色 | 承担 | 子连接数 |
|---|---|---|
| `data`(网页上是“数据”) | 新数据、重发的数据、回执 | 路径上设的数量(不改就是 8，范围 1 到 64) |
| `repair`(网页上是“补发”) | 需要重发的数据；只有当没有任何 `data` 子连接连着时才传新数据 | 路径上设的数量 |
| `control`(网页上是“回执”) | 只有回执 | 1 |

`data` 和 `repair` 不能放在同一条路径上。配对给你的就是一条角色为 `data` 的路径，起步时这就够用。如果线路在一个方向忙着传数据时，另一个方向丢包很多，再加一条独立的路径承担 `repair` 和 `control` 会有帮助，因为缺的数据块可以从第二条路径补上，回执也不用排在大量数据后面。

## 由哪个节点发起连接

只要两个节点里有一个能连到另一个，两边的规则就都能用。

- 规则所在的节点持有通往对端的路径时，它经这条路径打开子连接。
- 规则所在的节点**没有**路径时，它通过控制连接请对端从对端那一头打开子连接。请求里不带任何地址，对端按它自己的路径去拨。之后连接的承载方式和前一种情况完全一样。

所以只需要一个节点有另一个能连到的监听(`-listen`)，数据也不经第三台机器中转。如果两边互相都能连到，就给每一边各配一条通往对方的路径，这样每条规则用它自己所在节点的路径。规则也可以用 `-dial` 指定由哪个节点打开它的子连接，或者让两个节点为同一个会话都打开(见 `reference-cli.md`)。

由对端打开子连接的会话，比节点自己拨的会话起步稍晚，因为要先发请求、再等对端连过来。所以对端会预先备好几条连接，这样的会话就在其中一条上起步(见 `connecting.md` 的“备用连接”)。

对端离线时，没有路径的节点上的规则会立即重置它收到的连接，并在规则状态里说明原因。

## 路径的加密档位

| 档位 | 线路上 | 两端怎样确认对方 |
|---|---|---|
| `tls`(默认；网页上是“内置 TLS”) | TLS 1.3 | 两端各自出示身份证书；对方把其中密钥的指纹和配对时记下的进行核对 |
| `owncert`(网页上是“TLS,使用对端自有的证书”) | TLS 1.3 | 监听的一端出示你提供的证书(`-cert`、`-key`)。拨出的一端按证书密钥的指纹核对(`pin`)，或者像浏览器那样按签发机构和主机名核对(`ca`) |
| `off`(网页上是“关闭”) | 明文 TCP | 这一层什么都不做；用于已经被别的工具加密的路径。连到对端的 `-listen-plain` |

档位是路径的属性，在拨出节点上设置。在网页界面里，它是路径的“加密”一项。无论哪一档，连接开头都有一段简短的开场白，用配对时派生出的密钥证明拨出的是哪个节点。传输层对自己的消息也用同样的方式认证。每一档各自保护什么，见 `security.md`。

## 转发规则

**规则**告诉节点哪些连接要送到哪个对端。

**固定规则**在节点的某个地址上监听。连到那里的连接都会从对端那一头出来，去往规则的目的地，也就是一个从对端看过去的 IP 地址和端口。一条规则可以覆盖**一段端口**，逐个端口对应，例如 `50000-50010` 对 `50000-50010`。

**透明规则**是给装在路由器或网关上的节点用的。主机用 nftables 或 iptables 的重定向规则把连接重定向到节点。这条规则由你自己配置，tcpraid 不会去动主机的包过滤规则，除非节点带 `-redirect` 启动：那时它用 `nft` 把重定向规则写进节点自己的一张表(见 `reference-files.md`)。节点读出每条连接原本要去哪里，透明规则则规定哪些原始目的地送到哪个对端。连接在对端那一头会去往同一个地址。应用照常使用原来的地址。

**SOCKS5 规则**监听会说 SOCKS5 的程序。它没有目的地：每个程序在请求里说出目的地，连接从对端一侧出来后去往这个目的地。以名字给出的目的地由对端解析。

没有规则也可以要一条连接。`tcpraid connect` 向同一台主机上的节点要一条到对端那边某个目的地的连接，把它接在自己的标准输入和标准输出上，供那些靠运行一条命令来连服务器的程序使用。

不管连接从哪个入口进入节点，对端都按它为这个节点保存的允许列表检查目的地。

规则由节点保存，随节点一起启动。节点运行时可以新增、修改、停用和删除规则。一次改动只影响那一条规则，正在承载的连接会跑完。

## 会话

节点承载的每一条应用连接都是一个**会话**。“会话”页面、`tcpraid sessions` 和 `GET /api/v1/sessions` 会列出它们，带上所属规则、对端、字节数和子连接数。一个节点已有 64 个会话时，它的规则不再接受新连接。同一时间它最多为 64 个会话充当出口。

发送方结束时，数据可能还没有全部到达。节点会从应用那里提前读入数据，最多读到它的窗口那么多(默认 128 MB)。所以发送端的应用把数据写完并关闭连接的时候，数据流的一部分可能还在节点里或者在路上，远端还会继续接收一阵子。发送端节点上的会话，要等远端节点报告全部收到之后才结束。比对文件、或者根据结果做下一步，要等接收端的应用结束，而不是等发送端的应用返回。

会话带着一组传输层的设置运行，比如它的窗口，以及对端没有消息时它保持多久。它在开始时取得这些设置：规则设了就用规则的，否则用对端的，再否则用节点的。两个节点各取各的，谁也不会被告知对方的设置(见 `reference-files.md` 的“传输层的设置”)。

会话存在于两个节点的内存里。所有子连接都断了的时候，两个节点会把它保持 15 分钟，线路恢复后接着传。任何一个节点重启，会话就没了，应用会看到连接被重置，需要重试。重启的节点旁边的应用立刻就能看到，进程是被强行杀掉的也一样。另一个节点旁边的应用，在前一个节点被正常停止时也立刻就能看到。前一个节点是被杀掉的话，要等两个节点重新连上才看到。每个节点都会在控制连接上说明自己是进程的哪一次运行，一个节点听到对端换了一次运行，就重置它还为旧的那一次保留着的会话。节点一直不回来的话，另一个节点会把会话保持满那 15 分钟。被杀掉之前最后十秒左右才开始的会话，以及两个节点里有一个是 0.1.1 或更早版本时，也是这样。这几种情况列在 README 的“已知限制”里。

## 传输是怎么工作的

```
 app --> [ node ] ==== sub-connections (TCP, any path) ====> [ node ] --> destination
            ^                                                    |
            +--------------------- feedback ---------------------+
```

- **数据。** 发送端把数据流切成 256 KB 的块，分散到各条数据子连接上。每条子连接上只放它在自己的回执周期加 300 毫秒之内送得完的量，所以某一条卡住时，困在上面的数据很少。
- **回执。** 两端各自定期发送一份完整的状态快照：已经按序交付到哪里、手里有哪些乱序到达的块、哪些块缺失以及缺了多久。总是以最新的快照为准，所以丢了一份或者晚到一份没有任何代价。
- **丢失恢复。** 被报告缺失超过一秒的块会单独重发，走能最快送到的那条子连接，优先走另一条路径。
- **慢的成员会被换掉。** 一条子连接的交付速度远低于同路径上的其他子连接，或者 20 秒没有进展，就会被关闭并重新拨号。
- **结束。** 两个方向都完整结束的数据流会正常关闭。任何其他方式的结束都会重置应用的连接，这样被截断的数据流就不会被当成完整的。这包括节点停止、节点的进程被杀掉、配对被解除、目的地连不上、15 分钟耗尽。

### 回执通道

回执走数据子连接，如果你配了 `control` 路径也走那条路径，还可以选择走 UDP 数据报。数据报经过加密和认证，每份快照发一个，不重发。先到的那一份被采用。UDP 默认关闭，要自己配置。做法是在有可达 UDP 端口的节点上用 `-udp-listen ADDR` 启动，并在另一个节点上设置这个对端的 UDP 回执地址，用 `tcpraid peers set NAME -udp-dial HOST:PORT`，或者在网页界面的 对端 > 详情 > 高级 里设。在正向忙着传数据时反向丢包很多的线路上，UDP 回执有帮助。

格式见 `PROTOCOL.md`。
